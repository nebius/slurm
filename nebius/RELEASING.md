# Publishing a Nebius Slurm release

The `Publish Nebius Slurm release` workflow publishes a reviewed commit from a
`nebius/<release>` branch. It does not release commits from `master`, patch
branches, pull-request merge refs, or clean `slurm-<release>` mirrors.

## Repository setup

Before the first release, configure the GitHub repository as follows:

1. Enable immutable releases in the repository settings. The workflow fails
   after publication if GitHub does not report the release as immutable.
2. Create a `release` environment and add required reviewers. The workflow
   does not need environment secrets; the environment is the approval gate
   between building the artifacts and pushing the tag.
3. Protect `nebius/*` branches and require the normal patch comparison CI.

The workflow uses only the repository-provided `GITHUB_TOKEN`. No Nebius Cloud
credentials, package-registry credentials, or personal access token is needed.

The workflow and `nebius/ci/release/` must exist on the release branch from
which it is dispatched. New release branches receive them through `NB-0001`.
For an already-created release line, synchronize these paths from `master`
through a reviewed release-tooling pull request before publishing:

```sh
git restore --source=origin/master --staged --worktree -- \
  .github/workflows/slurm-release.yml \
  nebius/ci/release \
  nebius/RELEASING.md
```

## Release identity

The workflow derives the release identity exclusively from `META`. A stable
downstream release must have internally consistent values such as:

```text
Major:    26
Minor:    05
Micro:    3
Version:  26.05.3
Release:  nebius-1
```

This produces the annotated tag `slurm-26-05-3-nebius-1` and the runtime
version `26.05.3-nebius-1`. The separate `nebius` component prevents a Nebius
tag from colliding with SchedMD tags. Increase the final Nebius revision only
when publishing another downstream build of the same upstream patch version.

When the corresponding SchedMD patch release is not final yet, append an RC
suffix to `Release`:

```text
Release:  nebius-1-rc0
```

This produces tag `slurm-26-05-3-nebius-1-rc0`, runtime version
`26.05.3-nebius-1-rc0`, and a GitHub Release marked as a prerelease. Increment
the RC number for subsequent candidates. Drop the `-rcN` suffix for the stable
Nebius build; do not mark a release candidate as Latest.

## Publishing

1. Merge all intended patch pull requests into `nebius/<release>` and wait for
   their required checks to pass.
2. Copy the full 40-character tip commit with
   `git rev-parse origin/nebius/<release>`.
3. In GitHub Actions, select **Publish Nebius Slurm release**, choose the
   `nebius/<release>` branch in **Run workflow**, and paste the commit into
   `expected_commit`.
4. Select `make_latest` only when a stable release should become the
   repository's Latest release. The workflow rejects this option for an RC.
5. Review and approve the `release` environment after the build job has
   validated the candidate.

The explicit commit input prevents an operator from publishing a branch that
moved between review and dispatch. The workflow is safe to rerun: an existing
tag must point to the same commit, and an existing release must be immutable
and contain byte-identical assets.

## Published artifacts

Each GitHub release contains:

- a deterministic source archive from the exact tagged commit;
- OpenAPI JSON for the current and previous data parser versions, suitable for
  generating downstream clients such as a Nebius extension to
  `SlinkyProject/slurm-client`;
- a JSON manifest recording the branch, commit, Slurm version, tag, API
  versions, asset sizes, and SHA256 digests;
- `SHA256SUMS` covering the source archive, schemas, and manifest;
- GitHub/Sigstore build-provenance attestations for every published payload.

The OpenAPI files are generated by the just-built `slurmrestd`, not copied
from test snapshots. This ensures downstream-only REST operations are present
in the released schema.

After downloading assets, verify them with:

```sh
sha256sum -c SHA256SUMS
gh attestation verify \
  slurm-26.05.3-nebius-1.tar.gz \
  --repo nebius/slurm
```
